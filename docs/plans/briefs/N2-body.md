
# N2 - Gateway protocols: canonical conversion layer, `/v1/responses` (Codex), native Gemini inbound (research ideas #2 and #3)
1. **Canonical model.** Introduce an internal canonical request/response/stream-event model in `packages/gateway` (messages with text/image parts, tools + tool calls/results, reasoning parts, usage, finish reasons). Converters: OpenAI Chat <-> canonical, Anthropic Messages <-> canonical (refactor existing paths onto it), **OpenAI Responses <-> canonical**, **Gemini generateContent <-> canonical**; both requests and incremental streams, with an explicit finalize step that flushes terminal events and usage.
2. **New inbound endpoints:** `POST /v1/responses` (stream + non-stream, incl. tool calls and reasoning items; `previous_response_id` may return a clear unsupported error unless trivially supportable), native Gemini `POST /v1beta/models/{model}:generateContent` and `:streamGenerateContent` (SSE `alt=sse`). All route through Ferry's existing free-first router/handoff exactly like Chat/Messages do.
3. **Codex client support:** document and test pointing Codex CLI at Ferry's Gateway (`/v1/responses`) so Codex runs on Ferry's free routing; respect the Gateway's auth keys and limits.
4. Multimodal: accept image inputs where the selected upstream supports them (capability check), otherwise a clear 400; keep current text-only behaviour as the safe default for providers without vision.
5. Tests: golden conversion fixtures per protocol (request + stream sequences), Responses tool-call round trip, Gemini streaming, error shapes per protocol, finalize/usage correctness. Update `docs/GATEWAY.md` (remove the "/v1/responses not implemented" gap) and `docs/STATUS.md` known gaps.
