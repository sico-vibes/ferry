# Fix: intermittent ACP delegate race on Linux (no commit)
GitHub CI (ubuntu-latest) intermittently fails `packages/delegate/test/delegate.test.ts > external CLI adapters > runs the SDK fake ACP agent, streams updates, checkpoints writes and maps approval`: `expected 'Delegate completed without a final me…' to be 'Fake agent finished.'`. Failed on main commits c9c8905 and d9e6002 (twice, incl. a rerun), passed on others; always passes on Windows. The delegate code didn't change between those commits, so it's a timing race: the ACP adapter (packages/delegate, ACP/SDK client path) resolves the run's final message when the agent process exits / the prompt promise resolves, before the last `session/update` (agent_message chunk) notification has been processed — on Linux the process exit/stdio close ordering differs.
Fix the adapter so the final message is derived only after all pending session updates are drained: await the prompt response AND flush the notification queue (or wait for stdout end) before computing the final text; treat "no final message" only after the stream is fully closed. Do not weaken the test; add a regression test that delays the final update until after the prompt resolves / process exit (fake agent option) and asserts the final message is still captured. Typecheck/lint/prettier.
