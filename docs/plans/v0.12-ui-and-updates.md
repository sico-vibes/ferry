# v0.12 plan: fast updates, web preview, and a UI that meets the bar

Status: **in progress** (started 2026-10-04). Owner: Claude (CTO / orchestrator). Implementation: Luna (Codex `gpt-6-luna`, effort high). Functional QA: OpenCode (`deepseek-v4.1-flash`). Visual QA: Cursor `grok-4.7-high` (reads screenshots and references; read-only).

User references (annotated screenshots, the source of truth for this plan): `design/references/2026-10-04/01..11-*.png`.

## Product principles (apply to every lane)

- **Simple.** Nothing complicated. shadcn/ui is the alignment and spacing reference: consistent 4 px grid, one radius scale, controls that never wrap or squash, labels left and controls right, aligned left edges.
- **No sparkle/stars icons and no emoji** anywhere in the UI. lucide icons only, chosen for meaning.
- **No native OS dialogs** (`window.confirm/alert/prompt`, Electron `dialog.showMessageBox` for in-app actions). Use the shadcn `AlertDialog`/`Dialog`, themed.
- Separation by tone and spacing, hairlines only (`design/DESIGN-v2.md`); light and dark both first-class.
- Tooltips: instant (0 ms delay in collapsed rail), theme-coloured, never OS-native `title`.
- Information-dense where the user scans many items (providers, models, requests): tables and compact lists, not big cards.

## Workstreams

### P. Web preview + visual QA pipeline (first; everything else is reviewed through it)
- `pnpm preview:web`: the real renderer in a browser with a **fake backend** (mock client): seeded realistic data (multiple chats with long transcripts, streaming replies with thinking/tool activity, approvals, handoffs, providers in every state, models, gateway keys and a **live fake request stream**, usage history for 30 days). No network calls, no keys. A small scenario switcher (dev-only overlay or URL params: `?scenario=empty|busy|errors`, `?theme=light|dark`, `?size=1024x680`).
- The preview simulates the desktop title bar and window controls, so shell layout is reviewable in a browser.
- Optional static build (`pnpm preview:web:build`) for hosting later (publishing is the user's call).
- **Visual QA harness:** `pnpm shots:review <area>` captures the relevant states (light/dark, 1024x680 and 1440x900) into `.dev/review/<area>/`, and writes a review brief that pairs each capture with the matching reference image and the principles above. Grok reviews it (read-only) and returns findings with severity; Luna fixes; repeat until Grok and the orchestrator find nothing material.

### U. Updates that feel like updates
Today every update feels like a full reinstall and takes long. Target, following how major Electron apps ship (VS Code, Slack, Discord, Claude):
- Download in the background, **differential** (electron-updater blockmap) so only changed blocks transfer; full download only as fallback.
- Install **silently** on quit or via "Restart to update" (no installer wizard, no "choose options" pages on updates; the wizard is for first install only), app relaunches.
- Measure before/after: bytes downloaded and wall time for beta N to N+1; Defender-friendly packaging (fewer loose files, asar). Report numbers.
- In-app: an unobtrusive "Update ready, restart" affordance; release notes link.

### S. Shell (references 01, 02, 05, 08, 09)
- Full-width custom title bar like Claude Code: the whole top strip is draggable (`-webkit-app-region: drag`, interactive children `no-drag`), window controls in it (Windows overlay or custom), sidebar toggle, back/forward, and current project/chat in it. No dead zones.
- Sidebar: logo left edge aligned with the nav icons' left edge; collapsed rail tooltips instant and themed.
- User menu (bottom-left): Claude-style. Account line, items with aligned icons and shortcut hints (Settings `Ctrl+,`), theme as a compact segmented control or submenu (not a broken mixed list), Help, About/changelog, separators; menu width and alignment match the trigger.
- Replace every native dialog with styled `AlertDialog` (delete chat, discard, revoke key, ...).

### T. Settings as a dialog (reference 03)
- Settings opens as a large centered modal (like Claude): left nav with search, right content, close button; sections with label/description on the left and the control on the right; segmented controls never wrap; consistent row heights. Deep-linkable (`ferry://settings/<section>`, command palette).

### M. Models, providers and the picker (references 04, 07, 10)
- Provider logos: bundle a local, permissively licensed logo set (e.g. `@lobehub/icons-static-svg`/`-png`, MIT; check the licence and keep trademark notices in NOTICE), mapped by provider id, with a monogram fallback. No runtime fetching.
- Providers & keys: a real table (reference 10's right side is design inspiration only): logo + name, plan badge, status pill, usage meter, enabled switch, row actions; sortable; dense; no wrapping chaos; help text moved out of rows (tooltip or expandable detail).
- Models page provider cards: compact list/table, no giant empty cards, no squashed toggles.
- Model picker: search; grouped by provider with logos; profiles (Auto-Free, ...) as a compact first section; **hover card** with model details from the catalog: provider, description and strengths, release date, context window, parameters (when known), modalities, tool calling, speed and cost meters, free status. Never invent facts: show only catalog fields, hide what's unknown.

### H. Home (reference 06)
- Composer: remove the sparkle icon. Keep it clean.
- Replace the suggestion chips with useful statistics in the reference style: activity heatmap (past 30 days), messages/steps (you, this month), top models or providers used, free-tier savings. Real data from the core; empty states when new.

### G. Gateway as a first-class section (reference 11)
- Own sidebar entry. Dashboard: status and endpoint with copy buttons; "Use with ..." quick setup (OpenCode, Codex CLI, Continue/Cline, curl) with copyable snippets; key management (create with limits, copy once, revoke); stat tiles (requests, tokens, free vs paid, saved cost vs list price); a **real-time request log** (time, key, client, endpoint, model, provider, status, tokens, latency, cost) streamed from the core, filterable.
- Backend: persist a gateway request audit (new migration), stream events to the renderer, retention setting; never log prompt contents by default (metadata only; opt-in content logging is out of scope).

## Order and gates

1. **Now, in parallel:** P (web preview + QA harness) and U (updates).
2. Then S + T, then M + H, then G (two Luna lanes at a time). Every UI lane: Luna implements, the orchestrator runs gates, `shots:review`, Grok reviews against references, Luna fixes until it meets the bar, then **the user reviews in the web preview** before merge to `main`.
3. Gates as always: check (turbo concurrency 2), check-text, prettier, e2e 5 phases; CI on Windows and Ubuntu; beta per merge.
