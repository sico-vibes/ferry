# v0.11 plan: real-use fixes + gateway/routing upgrades (from New API research)

Status: **in progress** (2026-10-02). Orchestrated: Luna implements, OpenCode researches/QA, the orchestrator only briefs, verifies and merges.

## Wave F — fixes from the user's first real use of the v2 beta (priority, ships first)

| Lane | Problem (user report) | Root cause / direction |
|---|---|---|
| **F1 core responsiveness** | "Settings could not be saved: RPC request timed out: settings.update"; every change takes a long time to show | The installed core logged **19,373** `Provider model discovery failed` (hyperbolic, ~every 300 ms). `model-discovery.ts` never records a failure, so `refreshIfStale` treats the provider as stale on every call and every models/candidates/routing request fires a new network discovery → the core is saturated and RPCs time out. Fix: failure timestamp + exponential backoff per provider, discovery never awaited on request paths (background, de-duplicated), provider health shown once; event-loop lag monitor; audit other refresh-on-read loops. |
| **F2 seamless chat** | Replies show "Model", "This model doesn't share its reasoning", "Step usage: … tokens", "Agent run completed", a "Tools" list, big resolved approval cards, and stacks of long handoff chips with overflowing tooltips | One collapsed activity disclosure per assistant turn ("Worked for 12s · 3 steps"): thinking, tool calls/results, step usage, handoffs, resolved approvals and run status live inside it, collapsed by default. The visible message is only the model's answer. Pending approvals stay inline until decided, then fold into the chain. Handoffs become one compact line inside the chain; tooltips stay within the viewport. |
| **F3 shell polish** | Settings can't scroll; Windows title-bar buttons cover Share/drawer/⋯; confusing toasts ("Help: Help center is not connected in this preview", "About Ferry: Ferry desktop preview", "Cloudflare Workers AI updated"); interrupted banner misaligned | Settings content scroll container; header right padding = title-bar-overlay width; toast policy (only results of user actions and errors — no background-event toasts, no preview placeholders); real Help (opens docs/GitHub) and About (version dialog); interrupted banner aligned to the composer column. |

Exit: full gates green, screenshots of the transcript states, a real chat in the installed beta checked by the user.

## Wave N — New API ideas (idea-only; New API is AGPL-3.0, Ferry is MIT — never copy code). Research: `docs/research/newapi.md`

| Lane | Ideas | Scope | Effort |
|---|---|---|---|
| **N1 multi-key providers** | #1 multi-key + per-key health/rotation, #7 auto-disable/re-enable | Store N keys per provider (`(providerId, keyIndex)`), round-robin / weighted, per-key cooldown and disable, auto re-enable on probe, provider disabled only when all keys fail; explicit per-provider auto-disable toggle + status/keyword rules; Providers UI: add/remove/reorder keys | L |
| **N2 gateway protocols** | #2 conversion matrix, #3 Codex `/v1/responses` | Internal canonical request/stream model; inbound OpenAI Responses (`/v1/responses`) and native Gemini (`/v1beta/models/*:generateContent` / `:streamGenerateContent`) next to OpenAI Chat + Anthropic Messages; stream finalize step; Codex client works through the Gateway on free routing | L |
| **N3 mapping + overrides** | #4 model mapping, #5 param/header/status overrides | Logical model names → per-provider upstream IDs (catalog data + router resolution + gateway aliases); per-provider param strip/force, extra headers, status remap — declared in catalog/provider config | M |
| **N4 routing knobs** | #6 priority + weight, #8 account/key affinity | User priority/weight per provider layered on the computed score; session affinity to provider *key/account* (soft/strict) for cache hits and stable limits | M |
| **N5 accounting** | #9 cache-hit ratio, #10 gateway key token budgets | Price cached input tokens at a per-provider ratio in spend/quota estimates; gateway keys get tokens/min, tokens/day and concurrency caps with success-only counting | M |

Order: F1 + F2 + F3 in parallel → verify + beta → N3 + N4 + N5 in parallel (smaller, low conflict) → N1 → N2 → full rapid test pass → beta.
Every lane: own worktree from main, typecheck/lint/prettier in the sandbox, the orchestrator runs check + e2e outside; brief non-ASCII rule (no mojibake).
